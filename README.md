# secure_fs — защищённое файловое хранилище с поточным шифрованием RC4

## Описание

Программа `secure_fs` реализует защищённое хранилище файлов в едином контейнере (файле-образе). Каждый файл шифруется индивидуально с использованием поточного шифра **RC4** с уникальной **солью** (16 случайных байт), что исключает возможность повторного использования одного и того же ключевого потока для разных файлов.

### Ключевые особенности

- **Поточное шифрование RC4**: Самостоятельная реализация алгоритма «с нуля» без использования внешних криптобиблиотек.
- **Уникальная соль для каждого файла**: 16 случайных байт генерируются из `/dev/urandom` при добавлении файла.
- **Формирование ключа**: Seed для RC4 = `master_key + salt` (конкатенация мастер-ключа и соли).
- **Защита состояния**: Каждый файл шифруется новым, независимым контекстом RC4.
- **Структура контейнера**: Последовательные записи (заголовок + зашифрованные данные) без центральной таблицы файлов.
- **Работа с большими файлами**: Данные обрабатываются блоками по 4 КБ, не загружаясь целиком в память.
- **Многопоточное добавление**: Пул из 5 потоков для параллельной обработки файлов при добавлении директорий.
- **Рекурсивное добавление директорий**: Поддержка добавления директорий с сохранением относительных путей.

### Формат записи в контейнере

Каждая запись в образе имеет следующую двоичную структуру:

| Смещение | Размер (байт) | Поле | Описание |
|----------|---------------|------|----------|
| 0 | 4 | `data_size` | Размер зашифрованных данных (little-endian uint32) |
| 4 | 4 | `name_size` | Длина имени файла в байтах (little-endian uint32) |
| 8 | 16 | `salt` | Уникальная соль (16 случайных байт) |
| 24 | `name_size` | `filename` | Имя файла (UTF-8 строка без null-терминатора) |
| 24+`name_size` | `data_size` | `encrypted_data` | Зашифрованные данные файла |

**Важно:** Имя файла хранится как относительный путь от корня образа (например, `docs/manual.txt`). Это позволяет восстанавливать иерархию директорий.

## Требования

- Операционная система Linux (или WSL2 под Windows 11).

## Использование

### Синтаксис командной строки

Программа поддерживает три режима работы:

#### 1. Добавление файлов/директорий в образ

```bash
./secure_fs -add -key "masterkey" -image disk.img file1.txt dir1/ file2.bin ...
```

- Если файл образа не существует, он создаётся.
- Аргументы после `-image` могут быть как именами файлов, так и именами директорий.
- Для директории рекурсивно обходятся все файлы внутри неё и всех поддиректорий.
- Для каждого найденного файла генерируется соль, содержимое шифруется, и в образ дописывается новая запись.
- **Параллелизм:** Процесс добавления файлов выполняется в пуле потоков (максимум 5 потоков). Каждый поток берёт следующий файл из очереди, генерирует соль, шифрует и добавляет запись в образ. Для синхронизации записи в образ используется мьютекс.

#### 2. Просмотр списка файлов

```bash
./secure_fs -list -image disk.img
```

- Программа читает образ, извлекает из каждой записи имя файла (не расшифровывая содержимое).
- Выводит список в порядке возрастания имён (лексикографически).
- Для каждого файла выводится его размер (исходный, до шифрования) и имя.

#### 3. Извлечение файла

```bash
./secure_fs -get -image disk.img -key "masterkey" -out result_file file_name
```

- `file_name` – относительный путь файла внутри образа (например, `docs/manual.txt`).
- Программа ищет запись с таким именем в образе, читает соль и зашифрованное содержимое.
- Дешифрует содержимое с использованием мастер-ключа и соли.
- Сохраняет расшифрованный файл в `result_file`.
- Если файл с указанным именем в образе отсутствует, выводится ошибка.

### Примеры запуска

```bash
# Создание образа и добавление файлов
./secure_fs -add -key "MySecret" -image data.img notes.txt photo.jpg docs/

# Просмотр списка
./secure_fs -list -image data.img
# Ожидаемый вывод:
# docs/manual.txt     12345
# notes.txt           5678
# photo.jpg           98765

# Извлечение файла
./secure_fs -get -image data.img -key "MySecret" -out restored.txt docs/manual.txt
```

## Тестирование

### Быстрый тест

```bash
# 1. Создайте тестовый файл
echo "Секретное сообщение для проверки RC4 шифрования." > test.txt

# 2. Добавьте в контейнер
./secure_fs -add -key "test123" -image vault.bin test.txt

# 3. Просмотрите список
./secure_fs -list -image vault.bin
# Ожидаемый вывод: test.txt    53

# 4. Извлеките файл
./secure_fs -get -image vault.bin -key "test123" -out decrypted.txt test.txt

# 5. Проверьте целостность
diff test.txt decrypted.txt && echo "✅ Успех: файлы идентичны!"
```

### Тест безопасности (неверный пароль)

```bash
# Попытка извлечения с неправильным паролем
./secure_fs -get -image vault.bin -key "WRONG_PASSWORD" -out wrong_decrypt.txt test.txt

# Файл будет содержать «мусор», diff покажет различия
diff test.txt wrong_decrypt.txt
echo "✅ Защита работает: неверный пароль даёт некорректные данные"
```

### Тест с директорией (вложенность 4 уровня)

```bash
# Создайте структуру директорий
mkdir -p level1/level2/level3/level4
echo "File at depth 4" > level1/level2/level3/level4/deep.txt
echo "File at depth 2" > level1/level2/mid.txt

# Добавьте директорию рекурсивно
./secure_fs -add -key "DeepTest" -image deep.bin level1/

# Просмотрите список
./secure_fs -list -image deep.bin
# Ожидаемый вывод:
# level1/level2/level3/level4/deep.txt    16
# level1/level2/mid.txt                   16

# Извлеките файл из глубины
./secure_fs -get -image deep.bin -key "DeepTest" -out extracted.txt level1/level2/level3/level4/deep.txt

# Должно вывести: File at depth 4
```

### Тест больших файлов


## Технические детали

### Алгоритм RC4

Реализован самостоятельно в классе `RC4`:

1. **KSA (Key Scheduling Algorithm)**: Инициализация S-box ключом (seed = master_key + salt).
   - Создаётся перестановка S[0..255] = {0, 1, ..., 255}
   - Ключ циклически применяется для перемешивания S-box

2. **PRGA (Pseudo-Random Generation Algorithm)**: Генерация ключевого потока.
   - На каждом шаге генерируется один байт ключевого потока K
   - Входной байт XOR'ится с K для получения зашифрованного/расшифрованного байта

```cpp
// Инициализация (KSA)
for (int i = 0; i < 256; i++) S[i] = i;
for (int i = 0, j = 0; i < 256; i++) {
    j = (j + S[i] + key[i % key_len]) % 256;
    swap(S[i], S[j]);
}

// Генерация потока (PRGA)
i = (i + 1) % 256;
j = (j + S[i]) % 256;
swap(S[i], S[j]);
K = S[(S[i] + S[j]) % 256];
return byte ^ K;
```

### Формирование ключа (Seed)

```
RC4_SEED = master_key || salt
```

- `master_key` — пароль пользователя (строка из аргумента `-key`).
- `salt` — 16 случайных байт (генерируются для каждого файла из `/dev/urandom`).
- Seed передаётся напрямую в RC4 (без дополнительных хэш-функций).

### Многопоточность

При добавлении нескольких файлов или директорий используется пул потоков:

- **Максимум 5 потоков** (согласно заданию).
- **Очередь задач**: Файлы помещаются в очередь, потоки забирают их по мере доступности.
- **Мьютекс записи**: Доступ к файлу образа синхронизирован мьютексом, чтобы потоки не перемешивали данные при записи.
- **Условные переменные**: Потоки ожидают появления новых задач без активного ожидания (busy-wait).

```cpp
class ThreadPool {
    std::vector<std::thread> workers;  // 5 потоков
    std::queue<std::function<void()>> tasks;
    std::mutex queue_mutex;
    std::condition_variable condition;
};
```

### Обработка ошибок

Программа выводит сообщения об ошибках и возвращает ненулевой код возврата в случаях:

- Невозможность открыть контейнер или файл.
- Файл не найден в контейнере при извлечении.
- Некорректные аргументы командной строки.
- Отсутствие ключа (`-key`).
- Повреждённый формат образа (недостаточно байт для чтения заголовка).
- Превышение границ образа при чтении данных.

## Сравнение с secure_copy

| Характеристика | secure_copy | secure_fs |
|----------------|-------------|-----------|
| Шифр | XOR (caesar) | RC4 (поточный) |
| Параллелизм | 3 потока всегда | Пул до 5 потоков при добавлении |
| Хранение | Отдельные файлы | Единый контейнер (образ) |
| Соль | Нет | Уникальная для каждого файла (16 байт) |
| Ключ | Целое число (0-255) | Строка (мастер-ключ) + соль |
| Метаданные | Нет | Заголовок с размером, именем и солью |
| Иерархия | Плоская структура | Сохраняет пути директорий |
| Список файлов | Нет | Есть (без расшифровки) |

## Замечания

- **Имена файлов не шифруются**: Это позволяет выполнять команду `-list` без знания ключа и расшифровки содержимого. При необходимости можно доработать.
- **Нет удаления файлов**: Упрощённая модель — файлы только добавляются. При повторном добавлении файла с тем же путём создаётся новая запись (при извлечении используется последняя).
- **Порядок байт**: Все числовые поля записываются в порядке **little-endian**.
- **Атомарность**: Запись в контейнер не является атомарной операцией. Прерывание процесса во время добавления файла может повредить контейнер.
- **Безопасность**: RC4 является учебным алгоритмом и не рекомендуется для реального использования. В задании он используется для демонстрации принципов поточного шифрования.
