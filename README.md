# secure_copy — многопоточное копирование с шифрованием

## Описание

Программа `secure_copy` предназначена для параллельного шифрования (или дешифрования) нескольких файлов с использованием простого XOR-алгоритма (библиотека `libcaesar.so` из предыдущего задания). Она демонстрирует принципы многопоточного программирования в POSIX-системах: создание и управление потоками, синхронизацию доступа к общим ресурсам с помощью мьютексов, обработку взаимоблокировок с использованием таймаутов, а также обработку сигналов (SIGINT) для корректного завершения.

Программа всегда запускает ровно три рабочих потока. Каждый поток обрабатывает один файл целиком (чтение, шифрование, запись). Если файлов меньше трёх, часть потоков простаивает. Если файлов больше трёх, они помещаются в очередь и распределяются между потоками по мере освобождения.

После успешной обработки каждого файла в файл `log.txt` добавляется запись с временем, идентификатором процесса (PID), идентификатором потока (TID) и именем обработанного файла.

При получении сигнала `SIGINT` (Ctrl+C) программа корректно завершает работу: потоки прерывают обработку текущего файла, закрываются все открытые файлы и выводится сообщение `"Операция прервана пользователем"`.

## Требования

- Операционная система Linux (или WSL2 под Windows 11).
- Установленная библиотека `libcaesar.so` (из Задания 1). Библиотека должна находиться либо в текущей папке, либо в системном пути (например, `/usr/local/lib`).
- Компилятор `g++` с поддержкой C++11.
- Утилита `make`.
- Библиотека `pthread` (обычно входит в состав `build-essential`).

## Сборка

1. Поместите файлы `secure_copy.cpp`, `Makefile` и `libcaesar.so` в одну директорию.
2. Выполните команду:
   ```bash
   make secure_copy
   (или просто make, если цель all настроена на сборку secure_copy).

В результате будет создан исполняемый файл secure_copy.

Использование
Синтаксис командной строки:

bash
./secure_copy <файл1> [файл2] ... [файлN] <выходная_папка> <ключ>
<файл1> ... <файлN> — имена входных файлов (минимум один). Если файлов нет, программа выведет ошибку.

<выходная_папка> — имя папки, в которую будут помещены зашифрованные файлы. Если папка не существует, она будет создана.

<ключ> — целое число от 0 до 255, используемое для XOR-шифрования.

Примеры:

bash
# Шифрование трёх файлов
./secure_copy a.txt b.txt c.txt out 123

# Шифрование одного файла
./secure_copy document.txt secret 42

# Дешифрование (применяется тот же ключ)
./secure_copy secret/document.txt restored 42
После выполнения в папке out (или указанной вами) появятся файлы с теми же именами, но с зашифрованным содержимым. В текущей директории будет создан (или дополнен) файл log.txt с записями об обработке.

Логирование
Файл log.txt имеет следующий формат строки:

text
YYYY-MM-DD HH:MM:SS PID:12345 TID:12345678 filename.txt
Дата и время окончания обработки файла.

PID процесса.

TID потока (натуральный идентификатор, возвращаемый pthread_self()).

Имя обработанного файла (только имя, без пути).

Обработка сигналов
При нажатии Ctrl+C программа перехватывает сигнал SIGINT, устанавливает глобальный флаг завершения. Потоки, проверяющие этот флаг в циклах, прерывают обработку текущего файла и завершаются. Главный поток ожидает завершения всех рабочих потоков, выводит сообщение "Операция прервана пользователем" и завершает программу. Частично записанные выходные файлы не удаляются (при желании их можно удалить вручную).

Механизмы синхронизации и предотвращение взаимоблокировок
Мьютекс очереди: Доступ к очереди файлов (когда число файлов > 3) защищён мьютексом.

Таймаут: При попытке захвата мьютекса используется pthread_mutex_timedlock с таймаутом 5 секунд. Если мьютекс не удаётся захватить за это время, программа выводит сообщение об ошибке ("Cannot acquire queue mutex within 5 seconds – possible deadlock") и аварийно завершается с кодом 1.

Условные переменные: Для ожидания появления новых задач в очереди используются условные переменные, что позволяет избежать активного ожидания.

Тестирование
Для проверки работоспособности прилагается Makefile с целями:

make testfile — создаёт тестовый файл размером 10 МБ (test10M.bin) со случайными данными.

make test_secure — выполняет шифрование и дешифрование этого файла с ключом 123 и сравнивает результат.

make test_interrupt — запускает программу для проверки обработки Ctrl+C (требуется ручное нажатие).

Также можно протестировать на нескольких файлах:

bash
# Подготовка
echo "Hello" > file1.txt
echo "World" > file2.txt
mkdir out

# Шифрование
./secure_copy file1.txt file2.txt out 99

# Проверка (расшифровка)
./secure_copy out/file1.txt out/file2.txt dec 99
cmp file1.txt dec/file1.txt
cmp file2.txt dec/file2.txt
Структура проекта
secure_copy.cpp — исходный код программы.

Makefile — файл для автоматизации сборки и тестирования.

libcaesar.so — динамическая библиотека с функциями set_key и caesar (должна быть предоставлена отдельно).

Замечания
Библиотека libcaesar.so должна быть скомпилирована с флагами -fPIC и содержать функции с extern "C". Если библиотека находится не в текущей папке, укажите путь при линковке или установите её в систему (sudo make install из Задания 1).

Для корректной работы с таймаутами может потребоваться линковка с -lrt (в современных glibc это необязательно, но в Makefile флаг присутствует для совместимости).

При компиляции используются флаги -Wall -pthread.

# secure_fs — защищённый файловый контейнер с поточным шифрованием RC4

## Описание

Программа `secure_fs` реализует защищённое хранилище файлов в едином контейнере (файле-образе). Каждый файл шифруется индивидуальным потоком шифра **RC4** с использованием уникальной **соли** (16 случайных байт), что исключает возможность повторного использования одного и того же ключевого потока для разных файлов.

### Ключевые особенности:

- **Поточное шифрование RC4**: Реализация алгоритма «с нуля» без использования криптобиблиотек для самого шифрования.
- **Уникальная соль**: Для каждого файла генерируется случайная соль (16 байт из `/dev/urandom`).
- **Безопасное формирование ключа**: Итоговый ключ RC4 = `SHA-256(пароль || соль)`. Используется OpenSSL для SHA-256.
- **Защита состояния**: Каждый файл шифруется новым, независимым контекстом RC4.
- **Структура контейнера**: Последовательные записи (заголовок + зашифрованные данные) без центральной таблицы файлов.
- **Работа с большими файлами**: Данные обрабатываются блоками, не загружаясь целиком в память.

### Формат записи в контейнере:

| Смещение | Размер (байт) | Поле | Описание |
|----------|---------------|------|----------|
| 0 | 4 | `data_size` | Размер данных файла (little-endian) |
| 4 | 4 | `name_size` | Длина имени файла (little-endian) |
| 8 | 16 | `salt` | Уникальная соль (16 байт) |
| 24 | `name_size` | `filename` | Имя файла (строка) |
| 24+`name_size` | `data_size` | `encrypted_data` | Зашифрованные данные |

## Требования

- Операционная система Linux (или WSL2 под Windows 11).
- Компилятор `g++` с поддержкой C++17.
- Библиотека OpenSSL (`libssl-dev`) для функции SHA-256.
- Утилита `make` (опционально, можно собирать вручную).

## Сборка

### Вариант 1: Ручная компиляция

```bash
g++ -std=c++17 -o secure_fs secure_fs.cpp -lcrypto -O2 -Wall
```

### Вариант 2: Через Makefile

Если в проекте есть Makefile с целью `secure_fs`:

```bash
make secure_fs
```

В результате будет создан исполняемый файл `secure_fs`.

## Использование

### Синтаксис командной строки

Программа поддерживает три режима работы, задаваемые первым аргументом:

```bash
./secure_fs --key=<пароль> <режим> <аргументы...>
```

Пароль также можно передать через переменную окружения `SECURE_FS_KEY`.

#### Режимы:

1. **add** — добавить файл в контейнер:
   ```bash
   ./secure_fs --key=<пароль> add <контейнер> <файл>
   ```
   Если контейнер не существует, он создаётся. Файлы добавляются в конец.

2. **list** — вывести список файлов в контейнере:
   ```bash
   ./secure_fs --key=<пароль> list <контейнер>
   ```
   Выводит имена файлов и их размеры (в байтах). Не требует расшифровки.

3. **extract** — извлечь файл из контейнера:
   ```bash
   ./secure_fs --key=<пароль> extract <контейнер> <имя_файла> [выходной_файл]
   ```
   Если `выходной_файл` не указан, используется имя из контейнера.

### Примеры

```bash
# Создать контейнер и добавить два файла
./secure_fs --key=myStrongPassword add vault.bin notes.txt
./secure_fs --key=myStrongPassword add vault.bin photo.jpg

# Показать список файлов в контейнере
./secure_fs --key=myStrongPassword list vault.bin
# Вывод:
# notes.txt (1234 bytes)
# photo.jpg (567890 bytes)

# Извлечь файл
./secure_fs --key=myStrongPassword extract vault.bin notes.txt restored_notes.txt

# Использование переменной окружения
export SECURE_FS_KEY="mySecretKey"
./secure_fs add vault.bin document.pdf
./secure_fs list vault.bin
unset SECURE_FS_KEY
```

## Тестирование

### Быстрый тест

```bash
# 1. Создайте тестовый файл
echo "Секретное сообщение для проверки RC4 шифрования." > test.txt

# 2. Добавьте в контейнер
./secure_fs --key=test123 add vault.bin test.txt

# 3. Просмотрите список
./secure_fs --key=test123 list vault.bin
# Ожидаемый вывод: test.txt (53 bytes)

# 4. Извлеките файл
./secure_fs --key=test123 extract vault.bin test.txt decrypted.txt

# 5. Проверьте целостность
diff test.txt decrypted.txt && echo "✅ Успех: файлы идентичны!"
```

### Тест безопасности (неверный пароль)

```bash
# Попытка извлечения с неправильным паролем
./secure_fs --key=WRONG_PASSWORD extract vault.bin test.txt wrong_decrypt.txt

# Файл будет содержать «мусор», diff покажет различия
diff test.txt wrong_decrypt.txt
echo "✅ Защита работает: неверный пароль даёт некорректные данные"
```

### Тест больших файлов

```bash
# Создайте файл 50 МБ
dd if=/dev/urandom of=large_file.dat bs=1M count=50

# Добавьте в контейнер
./secure_fs --key=BigTest add large_vault.bin large_file.dat

# Извлеките и проверьте
./secure_fs --key=BigTest extract large_vault.bin large_file.dat restored_large.dat
md5sum large_file.dat restored_large.dat
# Хеши должны совпадать
```

### Полная очистка после тестов

```bash
rm -f test.txt decrypted.txt wrong_decrypt.txt vault.bin
rm -f large_file.dat restored_large.dat large_vault.bin
```

## Технические детали

### Алгоритм RC4

Реализован самостоятельно в классе `RC4`:
1. **KSA (Key Scheduling Algorithm)**: Инициализация S-box ключом.
2. **PRGA (Pseudo-Random Generation Algorithm)**: Генерация ключевого потока.

### Формирование ключа

```
RC4_KEY = SHA-256(global_password || salt)
```
- `global_password` — пароль пользователя (UTF-8 байты).
- `salt` — 16 случайных байт (генерируются для каждого файла).
- Результат — 32 байта (256 бит), используемые как ключ RC4.

### Обработка ошибок

Программа выводит сообщения об ошибках и возвращает ненулевой код возврата в случаях:
- Невозможность открыть контейнер или файл.
- Файл не найден в контейнере при извлечении.
- Некорректные аргументы командной строки.
- Отсутствие пароля (ни через `--key`, ни через `SECURE_FS_KEY`).

## Замечания

- **Имена файлов не шифруются**: Это позволяет выполнять команду `list` без расшифровки содержимого. При необходимости можно доработать.
- **Нет удаления файлов**: Упрощённая модель — файлы только добавляются. Для удаления требуется пересоздание контейнера.
- **Порядок байт**: Все числовые поля записываются в порядке **little-endian**.
- **Атомарность**: Запись в контейнер не является атомарной операцией. Прерывание процесса во время добавления файла может повредить контейнер.

## Сравнение с secure_copy

| Характеристика | secure_copy | secure_fs |
|----------------|-------------|-----------|
| Шифр | XOR (caesar) | RC4 |
| Параллелизм | Многопоточность (3 потока) | Однопоточный |
| Хранение | Отдельные файлы | Единый контейнер |
| Соль | Нет | Уникальная для каждого файла |
| Ключ | Целое число (0-255) | Пароль + SHA-256 + соль |
| Метаданные | Нет | Заголовок с размером и солью |
